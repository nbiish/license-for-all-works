## (B) MECHANISMS — Practical opt-out / opt-in a creator can deploy TODAY (ranked)

**Tier 1 — legally anchored in the EU and named in the GPAI Code of Practice:**

1. **robots.txt (RFC 9309)** — the only mechanism *explicitly named* in the GPAI Code of Practice copyright chapter, Measure 1.3(a): signatory GPAI providers commit to crawlers that "read and follow instructions expressed in accordance with the Robot Exclusion Protocol (robots.txt), as specified in the IETF RFC 9309." Deploy: `User-agent: *` + `Disallow: /` (or per-path), and also use `GPTBot`, `CCBot`, `ClaudeBot`, `Google-Extended` blocks. → [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309) · [Code of Practice Measure 1.3](https://ec.europa.eu/newsroom/dae/redirection/document/118115)
2. **TDMRep (W3C Community Group Final Report, 10 May 2024)** — the EU-born, ODRL-based standard: an HTTP header `tdm-reservation: 1` and/or `tdm-policy` pointing to a machine-readable ODRL policy; implements DSM Art 4(3) directly. Deploy as HTTP header on your site/asset URLs. → [TDMRep spec](https://www.w3.org/community/reports/tdmrep/CG-FINAL-tdmrep-20240510/) · [adoption trackers](https://deepwiki.com/w3c/tdm-reservation-protocol/4-adoption)
3. **ai.txt (Spawning)** — predictable `/.well-known/ai.txt` (and root `ai.txt`) file declaring commercial-TDM preferences for AI crawlers; voluntary preference signal; complements robots.txt. → [Spawning ai.txt via DataLicenses.org](https://datalicenses.org/initiatives/ai-txt/) · [spawning.ai](https://spawning.ai)
4. **"Have I Been Trained" (HIBT, Spawning)** — per-image opt-out registry for known training corpora (LAION, etc.); the effective *supplementary* signal for images already ingested. → [spawning.ai/trained](https://spawning.ai/trained)

**Tier 2 — Indigenous-governance opt-in/consent layers (additive to any license):**

5. **Local Contexts TK Labels + Notices** — community-authored labels (TK/BC) and notices (incl. **Open to Collaborate / OTC**, Non-Commercial, Community Use Only) that express *Indigenous* conditions on top of (never replacing) copyright; pair with your license; machine-readable via the Hub API and metadata integration (ArchivesSpace plugin, GBIF pilot, certified Integration Partners). Adoption (verified 31 Aug 2026): Hub accounts 51 communities / 58 institutions / 194 researchers / 34 countries; 45 subscriber institutions; 10 Working Groups with 1,100+ members. → [Local Contexts](https://localcontexts.org/) · [Annual Report 2024–25](https://localcontexts.org/2024-2025-annual-report/) · [GBIF pilot](https://localcontexts.org/gbif-pilot-using-tk-and-bc-labels/)
6. **CARE Principles (Collective benefit / Authority to control / Responsibility / Ethics)** — governance framework to cite in license preamble and data-management statements; increasingly referenced by funders/repositories. → [CARE (GIDA/RDA)](https://www.rd-alliance.org/wp-content/uploads/2024/04/CARE20Principles20for20Indigenous20Data20Governance_FINAL_Sept2006202019.pdf)

**Tier 3 — metadata + file-format attachment:**

7. **SPDX license expressions with `LicenseRef-`** — embed `licenseExpression: "LicenseRef-<Your-Custom-License-Id>"` in SBOM/JSON-LD/metadata of artworks, 3D models, software; publish the custom license text in your SPDX document. (Correction: there is no SPDX `expressedFor` property; the mechanism is `licenseExpression` on an SpdxItem + `LicenseRef-` identifiers.) → [SPDX 3.0.1 spec](https://spdx.github.io/spdx-spec/v3.0.1/model/SimpleLicensing/Properties/licenseExpression/)
8. **schema.org JSON-LD (`license`, `usageInfo`)** — attach to web pages/social posts and image metadata so search engines and crawlers see license + usage terms. → [schema.org usageInfo](https://schema.org/usageInfo) · [schema.org license](https://schema.org/license)
9. **rightsStatements.org** — standardized GLAM statements (e.g., `InC`, `InC-RUU`, `NoC-NC`) for collection objects; URL-citable in metadata. → [rightsstatements.org](https://rightsstatements.org/en/)
10. **3D file embedding** — **glTF:** `asset.copyright` field + custom `asset.extras` (JSON-LD/SPDX); no license field in core spec, so use extras or sidecar; glTF-Sample-Assets use a metadata system incl. REUSE/SPDX. **STL:** *no* metadata capability (binary STL = 80-byte header) → ship a sidecar `.json`/`.txt` (SPDX/JSON-LD) alongside, or convert to glTF/3MF (3MF supports metadata). → [glTF asset spec](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) · [glTF-Sample-Assets metadata](https://github.com/KhronosGroup/glTF-Sample-Assets)
11. **Commission "opt-out protocols" process (watch item)** — the Commission (answer of 20 Feb 2026, EVP Virkkunen) is running a facilitated process per Measure 1.3(b) to agree "state-of-the-art, technically implementable, and widely adopted" opt-out protocols; a 2025–26 stakeholder consultation evaluated **7 protocols** with strong rightsholder disagreements. No single standard is yet "recommended" — so deploy TDMRep + robots.txt + ai.txt in parallel. → [EP answer E-005023/2025 (PDF)](https://www.europarl.europa.eu/doceo/document/E-10-2025-005023-ASW_EN.pdf) · [CEPIC consultation summary](https://www.cepic.org/posts-for-members/ai-opt-out-protocols-where-are-we-results-of-the-eu-consultation)

**Practical stack for an Indigenous creator today:** `robots.txt` (RFC 9309) + `tdm-reservation: 1` header (TDMRep) + `ai.txt` + HIBT opt-out + TK/OTC Labels via Local Contexts + SPDX `LicenseRef-` + schema.org JSON-LD on every asset page, and (for 3D) glTF extras or sidecar files. **Note:** all of these are preference signals with voluntary enforcement — none prevents copying by itself; enforcement relies on EU copyright law (Art 4(3) DSM, Art 53(1)(c) AI Act) and platform policy.
